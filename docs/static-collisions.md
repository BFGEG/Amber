# Статические коллайдеры и стены — задачи #8 и #9

Базовая ветка — `feat/7-fixed-step`, предыдущий PR —
[#104](https://github.com/BFGEG/Amber/pull/104).

`src/world.rs` задаёт размеры платформ и стен. Из этих же данных создаются
видимая геометрия и игровые области AABB в мировых координатах. Земля имеет
верхнюю грань на y=0 и толщину 0,2 м вниз. Небо и части фигуры персонажа
не становятся отдельными препятствиями.

Персонаж имеет постоянный объём 1×1×1,75 м с началом в точке ног.
Он охватывает модель при горизонтальном повороте и не вращается вместе с ней.
Горизонтальное движение проверяется по всему пути за шаг: сначала до ближайшего
контакта, затем вдоль свободной оси. Это предотвращает прохождение через тонкую
стену и диагональный проход насквозь через небольшой блок. Зазор у контакта —
0,0001 м. Одновременный контакт с двумя стенами блокирует обе оси.

Персонаж должен начинать вне препятствий: исправление начального пересечения
не входит в этот контроллер. Вертикальное движение, опора и прыжок описаны
в [блоке #10–#11](gravity-jump.md). Столкновения камеры — #13.

## Запуск и проверка

```sh
cargo run --locked
```

F3 включает и выключает каркасы: зелёные — препятствия, оранжевый — персонаж.
Клавиша обрабатывается однократно на нажатие. Для включения сразу при запуске:

```sh
AMBER_COLLIDER_DEBUG=1 cargo run --locked
```

Каркасы нарисованы тонкими кубами чуть снаружи математических границ
(отступ 0,025 м), чтобы избежать мерцания на поверхности. Они служат только
для проверки, не участвуют в столкновениях и используют общую геометрию куба.

На полигоне есть пять исходных платформ, отдельная стена с центром (1, 1, 8)
и угол из двух стен около (12, 0, 7). Проверить:

1. Включить F3 и сверить каркасы с платформами; каркас персонажа следует за ним.
2. Упереться в бок платформы или стены: корпус останавливается снаружи.
3. Двигаться к стене по диагонали: персонаж скользит вдоль неё.
4. Удерживать движение во внутренний угол: нет проникновения и дрожания.
5. Отойти от стены, повернуть камеру, выключить F3: управление остаётся доступным.

`AMBER_TIMING_DEMO=1` использует свободную полосу z=-6 в стороне от препятствий,
чтобы сохранить проверку 26 м за 120 шагов из #7.

Автоматические проверки покрывают тонкую стену с обеих сторон, скольжение,
отход от контакта, диагональный проход к конечному блоку, устойчивый угол при
разном порядке препятствий, отсутствие горизонтальной реакции на землю и
объекты над головой. Контакт и скольжение проверяются при 30, 60 и 144 FPS
симуляции. Команды общих проверок приведены в `AGENTS.md`.

В текущем окружении прошли форматирование, `cargo check --locked`, clippy
и все 13 тестов. В X11 визуально проверены статические каркасы и объём
персонажа при включении через `AMBER_COLLIDER_DEBUG=1`. Автоматическая доставка
клавиш в окно не позволила надёжно проверить F3 и ручное управление; проход
по пунктам выше остаётся проверкой перед слиянием.
